- (나) 🔍 매트릭스에서 필요 이상으로 보이는 ○ 를 하나 고르고, 그 이유와 그 ○ 가 남아 있을 때의 위험을 적어 주세요.

  - 쓸 내용: ① 칸이 없을 때의 결과 ② 칸이 있을 때의 결과 ③ 파일을 고칠 사람과 시각
  - 답:

## 6교시 · 권한 판정 함수 `check_permission`

### 문제 6-1 · 권한 판정 함수 `check_permission` 직접 쓰기

- (가) 채우기 전에 실행한 출력 아홉 줄과, 내가 채운 코드를 붙여 넣어 주세요.
  - 쓸 내용: ① 채우기 전 출력 아홉 줄 ② `# ←` 다섯 곳에 채운 코드
  - 답:

    터미널 위치를 `security-agent-toolkit/access_control`로 맞추고 `rbac.py`와 `day01_6-1_run.py`를 만들었다. 검사를 채우기 전 내 PC에서 실행한 출력 아홉 줄은 다음과 같다.

    ```text
    seoyeon SALES QUERY -> True 허용
    seoyeon SETTLE QUERY -> True 허용
    junho SETTLE QUERY -> True 허용
    junho SALES CHANGE -> True 허용
    dami SALES QUERY -> True 허용
    minsu SALES QUERY -> False 등록되지 않은 사용자
    gaeun ACCOUNT CHANGE -> True 허용
    batch-night SETTLE QUERY -> True 허용
    tester SALES QUERY -> True 허용
    ```

    검사 [1]인 사용자 등록 여부만 있어서 minsu만 거부됐고, 나머지는 마지막 `return True, "허용"`까지 내려갔다. 오류 없이 실행됐지만 권한 판정은 불완전한 상태였다.

    AI 설명을 참고해 다섯 위치에 추가한 코드는 다음과 같다. 함수 안쪽의 코드이므로 기본 들여쓰기는 4칸이고 `if` 안의 `return`은 8칸이다.

    ```python
        # [2]-1: 재직 여부
        if not USERS[user]["employed"]:
            return False, "퇴사한 계정"

        # [3]-1: 역할 꺼내기
        role = USERS[user]["role"]

        # [3]-2: 역할 정의 여부
        if role not in ROLES:
            return False, "역할이 없음"

        # [4]-1: 요청한 권한 이름 만들기
        permission = f"{resource}:{action}"

        # [4]-2: 역할에 그 권한이 있는지 확인
        if permission not in ROLES[role]:
            return False, "권한 없음"
    ```

    문자열을 합쳐 `SALES:QUERY` 같은 권한 이름을 만든 뒤 그 역할의 허용 목록에 있는지 확인한다. 거부 조건에 걸리면 `return`으로 이유와 함께 함수를 끝내고, 모든 검사를 지나야 마지막 허용을 반환한다.

  - 쓸 내용: 자유롭게
  - 답:

    기록 재판정은 과거 요청의 사용자·자원·행위를 현재 함수에 전달해 다시 판단하는 것이며, 과거 서버에 요청을 재전송하거나 이미 일어난 일을 바꾸는 것은 아니라는 점을 배웠다. 허용된 요청의 사용 권한만 모아 역할에 부여한 목록과 비교하고, 이번에 쓰이지 않았다는 사실과 업무에 필요 없다는 판단은 구분해야 한다.

    코드를 먼저 작성해 검수를 요청했을 때 허용 분기에서 전체 건수를 늘리는 `allowed = allowed + 1`이 빠져 있었다. 사용자별 counts를 늘려도 allowed가 자동으로 늘어나지는 않는다는 설명을 듣고 한 줄을 추가했다.

    그 뒤 실제 실행은 두 번째 import 줄에서 `ModuleNotFoundError: No module named 'access_log'`로 멈췄다. 분석 코드와 별개로 기록을 담은 `access_log.py`가 같은 폴더에 필요하다는 설명을 받고 파일을 작성했다. cat으로 LOG 15건을 확인한 뒤 다시 실행해 허용 7건·거부 8건과 미사용 일곱 줄을 직접 확인했다.

    이번 실습을 통해 코드를 실행하는 파일, 함수를 담은 파일, 입력 기록을 담은 파일의 역할을 구분하게 됐다. 아직 코드를 혼자 설명하기는 어려워 출력 한 줄과 변수의 의미를 다시 해설받으며 정리했다.
