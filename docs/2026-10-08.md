# 2026-10-08 (목)

## 오늘 새로 쓴 명령
git config, git add, git commit, git push

추가로 `pwd`, `cd ..`, `git status`, `git log --oneline`도 사용하거나 확인했다.

## 찾아보고 알게 된 것
오늘은 웹에서 파일을 직접 올리는 대신 터미널 명령어로 실습 파일을 GitHub에 올렸다. 강사님이 순서를 정정해 주셔서 학습 노트를 먼저 만들고 실습 파일과 함께 커밋한 다음 푸시했다.

`add`는 다음 커밋에 넣을 변경을 선택하고, `commit`은 선택한 내용을 내 PC에 기록하며, `push`는 그 기록을 GitHub로 보내는 단계다. 처음에는 업로드 과정으로 묶어서 생각했는데, 각각 역할이 다르다는 것을 알게 됐다.

untracked는 아직 Git이 추적하지 않는 파일이고, tracked는 Git이 추적 중인 파일이다. staged는 다음 커밋에 넣도록 변경을 선택한 상태다. `git status`를 볼 때 파일 이름뿐 아니라 어느 제목 아래에 있는지도 확인해야 한다.

GitHub에서 여러 파일 옆에 같은 커밋 메시지가 보여서 잘못 올린 것인지 궁금했다. 확인해 보니 함께 커밋한 파일들에 같은 작업 설명이 표시된 것이었다. 파일 내용에 문장이 들어간 것은 아니어서 그대로 두기로 했다.

## 막힌 것
처음 터미널이 `agent_core` 폴더에서 열려 있어 상위 폴더로 이동하는 방법을 확인했다. `cd ..`로 한 단계 위로 이동하고 `pwd`로 위치를 확인하면 됐다.

학습 노트를 어떤 형식으로 만들어야 하는지도 헷갈렸다. VS Code에서 파일 이름을 `2026-10-08.md`로 지정해 Markdown 파일로 만들었다.

`git add`를 실행하자 `LF will be replaced by CRLF` 경고가 여러 줄 나왔다. 오류인 줄 알고 질문했는데 줄바꿈 변환에 관한 경고였다. 이후 `git status`로 선택된 파일을 확인했다.

상태 목록이 길어서 학습 노트가 빠진 줄 알았다. 다시 살펴보니 `Changes to be committed` 마지막에 `docs/2026-10-08.md`가 들어 있었다. 삭제된 파일이나 캐시 파일도 함께 선택될 수 있다는 점을 확인했다.

`git log --oneline` 실행 후에는 평소 터미널과 다른 화면이 나와 어떻게 나오는지 몰랐다. 커밋 기록을 보는 화면이었고, `q`를 누르면 터미널로 돌아올 수 있었다.

마지막으로 GitHub에 직접 들어가 실습 파일과 학습 노트가 반영된 것을 확인했다.
