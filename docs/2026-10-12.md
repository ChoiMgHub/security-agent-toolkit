# 2026-10-12 (월)

## 오늘 설치한 것
- Wireshark 4.6.9 x64를 설치했다. USBPcap은 이번 수업에서 쓰지 않아 체크를 해제했다. 설치 후 Wireshark를 열었을 때 네트워크 인터페이스 목록이 보였고, 옆의 그래프도 실시간으로 움직였다.

## 찾아보고 알게 된 것
- 보안 담당자가 패킷을 직접 열어 보는 이유는 통신이 실제로 어떻게 오갔는지 확인하기 위해서다. 로그에 오류나 수상한 접속이 보였을 때 패킷의 출발지·목적지, 사용한 프로토콜, 오간 순서를 보면 원인을 좁히는 데 도움이 된다.
- 패킷은 네트워크를 통해 오가는 데이터의 단위다. 내용만 있는 것이 아니라 어디로 보내는지 등을 판단하는 정보도 함께 담긴다.
- Npcap은 Windows에서 네트워크 패킷을 잡을 수 있게 해 주는 드라이버와 라이브러리다. Wireshark가 캡처한 패킷을 보여 주고 분석하려면 이 기능이 필요하다는 것을 알게 됐다.
- `|`(파이프)는 앞 명령의 출력을 뒤 명령의 입력으로 넘긴다. `network_zt` 폴더에서 `tasklist`, `tasklist | grep Code`, `tasklist | grep code`를 직접 실행해 결과를 비교했다.

## 막힌 것
- 설치 중 USBPcap 체크가 필요한지 헷갈려 확인했다. 이번 수업에는 필요하지 않아 체크를 해제하고 설치를 계속했다.

## 다음에 확인할 것
- 오후 수업에서 실제 패킷 캡처를 시작하고, 선택한 인터페이스에 어떤 패킷이 나타나는지 확인해 보고 싶다.
