# 2026-10-12 (월)

## 오늘 설치한 것
- Wireshark (Npcap 함께): Windows PC에서 설치·실행 여부를 확인한 뒤 실제 결과와 버전을 기록할 예정.

## 찾아보고 알게 된 것
- 보안 담당자가 패킷을 직접 열어 보는 이유는 통신이 실제로 어떻게 오갔는지 확인하기 위해서다. 로그에 오류나 수상한 접속이 보였을 때 패킷의 출발지·목적지, 사용한 프로토콜, 오간 순서를 보면 원인을 좁히는 데 도움이 된다.
- 패킷은 네트워크를 통해 오가는 데이터의 단위다. 내용만 있는 것이 아니라 어디로 보내는지 등을 판단하는 정보도 함께 담긴다.
- Npcap은 Windows에서 네트워크 패킷을 잡을 수 있게 해 주는 드라이버와 라이브러리다. Wireshark가 캡처한 패킷을 보여 주고 분석하려면 이 기능이 필요하다는 것을 알게 됐다.
- `|`(파이프)는 앞 명령의 출력 내용을 다음 명령의 입력으로 넘긴다. `tasklist | grep Code`라면 실행 중인 프로그램 목록에서 `Code`가 들어간 줄만 골라 보는 식이다. 실제 출력과 대소문자 차이는 내 터미널에서 확인할 예정이다.

## 막힌 것
- 현재 이 기록을 준비한 환경에서는 내 Windows PC의 설치 화면과 VS Code 터미널을 확인하지 못했다. 설치 성공, 인터페이스 표시, 명령 실행 결과를 확인한 것처럼 적지 않았다.

- `security-agent-toolkit` 바로 아래에 `network_zt` 폴더를 만들고 `pwd`로 위치 확인하기.

- 저장소 루트에서 `git status`로 변경 목록과 민감한 파일을 먼저 확인한 다음 `git add .` 전후 상태 확인하기. 이미 추적 중인 캐시 파일은 `.gitignore`만으로 추적이 해제되지 않는다는 점도 기억하기.
