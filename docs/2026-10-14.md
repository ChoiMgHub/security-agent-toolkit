# 2026-10-14 (수) 아침 과제

## 찾아본 것

서버에서 로그를 옮기고 백업하는 방법:

처음에는 컴퓨터에서 마우스로 복사하고 삭제할 수 있는데, 왜 같은 일을 명령어로 다시 배우는지 이해가 잘되지 않았다. 파일을 다루는 기능 자체는 비슷하지만, 서버를 원격으로 관리할 때는 터미널에서 작업하는 경우가 많다는 설명을 듣고 이유를 이해했다. 모든 서버에 마우스가 없다는 뜻이 아니라, 화면과 마우스를 쓰기 어려운 환경에서도 파일을 다룰 수 있도록 배우는 것이다.

로그를 백업할 때는 원본을 남긴 채 복사본을 만드는 `cp`를 사용할 수 있고, 로그의 위치를 바꾸거나 이름을 바꿀 때는 `mv`를 사용할 수 있다. 파일 한두 개를 다룰 때는 마우스로 해도 되지만, 많은 파일을 반복해서 처리하거나 정해진 시간마다 백업하려면 명령어를 스크립트로 묶어 자동으로 실행하는 방식이 도움이 된다. 오늘 배우는 명령어가 나중에 서버 관리와 자동화의 기초가 된다는 점을 알게 됐다.

백업한다고 무조건 안전한 것도 아니었다. 복사할 위치에 같은 이름의 파일이 있으면 기존 내용을 덮어쓸 수 있으므로 `cp -i`로 먼저 묻게 하는 방법도 함께 익혀야 한다. 작업 전에는 `pwd`로 위치를 확인하고, 작업 후에는 `ls`나 `cat`으로 결과를 확인해야 한다.

오늘은 삭제 연습도 하기 때문에 저장소 `security-agent-toolkit`의 바깥에 `mvcp_practice` 폴더를 만들어 연습하도록 되어 있다. 연습용 로그와 폴더는 GitHub에 올리는 대상이 아니고, 공부한 내용을 적은 `docs/2026-10-14.md`가 기록으로 남길 파일이다.

## 오늘 새로 쓴 명령

touch, cp, mv, rm, Tab 자동 완성

| 명령·기능 | 내가 이해한 뜻 | 오늘 과제에서 사용하는 예 |
|---|---|---|
| `touch` | 없는 파일이면 빈 파일을 만든다. 이미 있으면 내용을 유지하고 접근·수정 시각을 갱신한다. | `touch memo.txt` |
| `cp` | 파일이나 폴더를 복사한다. 원본은 그대로 남는다. | `cp a.log b.log` |
| `mv` | 파일이나 폴더의 이름을 바꾸거나 다른 위치로 옮긴다. | `mv b.log c.log`, `mv c.log backup/` |
| `rm` | 지정한 파일을 삭제한다. 기본 동작으로는 폴더를 삭제하지 않는다. | `rm memo.txt` |
| Tab 자동 완성 | 이름의 앞부분을 입력하고 Tab을 눌러 나머지를 완성한다. | `cd mvcp` 입력 후 Tab |

같이 사용한 명령어의 뜻도 정리했다.

- `pwd`: 현재 내가 어느 폴더에 있는지 확인한다.
- `ls`: 파일과 폴더 목록을 확인한다. `ls backup`은 `backup` 안의 목록을 보여 준다.
- `mkdir`: 폴더를 만든다. 처음에는 단순히 “생성”이라고 정리했는데, 정확히는 “폴더 생성”이다.
- `cat`: 지정한 파일의 내용을 터미널에 보여 준다.
- `cd`: 작업할 폴더로 이동한다. `cd ..`는 한 단계 상위 폴더로 이동하는 뜻이다.
- `echo "내용" > 파일`: 내용을 파일에 저장한다. 같은 파일이 있으면 기존 내용을 덮어쓰므로 주의해야 한다.

## 찾은 옵션

폴더째 복사 - `-r` / 덮어쓰기 전에 묻기 - `-i` / 폴더째 지우기 - `-r`

| 하고 싶은 일 | 명령어 | 확인할 결과 |
|---|---|---|
| 폴더와 안의 내용까지 복사하기 | `cp -r backup backup2` | `backup2` 안에도 `c.log`가 있어야 한다. |
| 같은 이름이 있으면 덮어쓰기 전에 묻게 하기 | `cp -i a.log backup/` | 같은 명령을 두 번째 실행하면 덮어쓸지 묻는지 확인하고, `n`으로 거절한다. |
| 폴더와 안의 내용까지 삭제하기 | `rm -r backup2` | `backup2`가 목록에서 없어져야 한다. |

처음에는 `-r`이 단순히 “파일을 한꺼번에 전부 처리한다”는 뜻인 줄 알았다. 다시 질문해 보니 정확히는 “지정한 폴더 안으로 들어가 파일과 하위 폴더까지 처리한다”는 뜻이었다. `r`은 recursive를 뜻한다.

`-r`만 보고 복사인지 삭제인지 정하는 것은 아니다. 앞에 `cp`가 있으면 복사하고, `rm`이 있으면 삭제한다. `rm -r backup2`는 `backup2`와 그 안의 내용이 대상이고, 옆에 있는 `backup`이나 `a.log`까지 지우는 것은 아니다.

또한 `rm`이 꼭 파일 하나씩만 지우는 명령도 아니다. `rm a.log b.log`처럼 여러 파일을 지정할 수 있다. 여러 파일을 지정하는 것과 폴더 내부까지 처리하는 `-r` 옵션은 다른 개념이다. 오늘 삭제 실습에서는 과제 지시대로 지정한 대상만 처리하고, 강제 삭제 옵션이나 `*`는 사용하지 않는다.

## mv 의 두 가지 쓰임

이름 바꾸기:

```bash
mv b.log c.log
```

같은 위치에서 `b.log`의 이름을 `c.log`로 바꾼다. 복사본을 만드는 것이 아니므로 기존 이름 `b.log`는 남지 않는다. 파일 안의 로그 내용을 편집하는 명령은 아니어서 내용은 그대로다. 폴더의 이름을 바꿀 때도 내부 파일과 내용을 그대로 유지한다.

옮기기:

```bash
mv c.log backup/
```

이미 만든 `backup` 폴더 안으로 `c.log`를 옮긴다. 이 경우 파일 이름과 내용은 그대로이고 위치가 바뀐다. 원래 위치에서는 보이지 않고, `ls backup`으로 옮겨진 파일을 확인할 수 있다.

나는 `mv`가 파일 내용까지 바꾸는지 궁금해서 다시 질문했다. 이름이나 위치를 바꾸는 것과 파일 내용을 수정하는 것은 다르다는 점을 이해했다. 다만 목적지에 같은 이름의 파일이 이미 있으면 덮어쓸 수 있으므로, “내용을 편집하지 않는다”는 것이 “기존 파일을 잃을 일이 없다”는 뜻은 아니다.


처음에는 과제 설명을 읽어도 내가 구체적으로 무엇을 해야 하는지 잘 잡히지 않았다. 다시 한 단계씩 설명을 듣고 나서, 저장소 밖에서 파일 작업을 연습하고 → 기록을 작성해서 올리고 → 기록 일부를 수정해서 다시 올린 다음 → GitHub에서 바뀐 줄을 확인하는 순서라는 것을 이해했다.

**명령어로 작업하는 이유**

마우스로 이미 할 수 있는 작업을 굳이 명령어로 하는 이유가 궁금했다. 서버에서 터미널로 작업하는 경우와 반복 작업을 자동화하는 경우를 생각하니 이유가 이해됐다. 명령어를 쓰면 무조건 더 좋다는 뜻이 아니라, 사용하는 환경과 작업 규모에 따라 필요하다는 점을 알게 됐다.

**Tab 자동 완성 뒤에 붙은 슬래시**

`cd mvcp`까지만 입력하고 Enter를 누르기 전에 Tab을 누르니 `cd mvcp_practice/`로 완성됐다. 설명의 예시와 달리 끝에 기호가 붙어서 궁금했다. 내가 처음에는 역슬래시라고 생각했는데, 실제로 적힌 문자는 `/`인 슬래시였다. 폴더임을 나타내며 자동 완성 과정에서 붙은 것이고, 이번 상황에서는 `cd mvcp_practice`와 `cd mvcp_practice/` 모두 같은 폴더로 이동한다는 것을 알게 됐다. `mvcp_practice/backup`처럼 하위 폴더 경로를 이어 적을 수도 있다.

**rm과 -r의 차이**

파일 하나는 `rm memo.txt`로 지울 수 있는데 폴더에는 왜 `-r`이 필요한지 이해가 잘되지 않았다. `rm`은 기본 동작으로 폴더를 지우지 않고, `-r`을 붙이면 내부 파일과 하위 폴더까지 처리해 폴더 자체도 지운다는 것을 알게 됐다. “모든 파일”이라는 표현만 외우기보다 어느 폴더를 대상으로 지정했는지 먼저 확인해야 한다.

**삭제하면 기록도 없어지는지**

보안 수업인 만큼 명령어로 삭제하면 작업 기록이 남지 않고 완전히 삭제되는 것인지 궁금했다. 파일 삭제와 작업 기록은 별개였다. 셸 설정에 따라 입력한 명령이 이력에 남을 수 있고, 시스템의 감사 설정에 따라 삭제 관련 보안 기록도 남을 수 있다. `rm`은 작업 흔적까지 없애는 명령이 아니고, `-r`도 완전 삭제 기능이 아니라 처리 범위를 폴더 내부까지 넓히는 옵션이다.

**휴지통을 거치지 않는데 복구가 가능한 이유**

`rm`으로 지운 파일이 휴지통으로 가지 않는다면 어디로 가는지도 궁금했다. 삭제 파일을 다른 보관소로 옮기는 것이 아니라, 파일을 일반적인 목록에서 찾아 열 수 없게 처리하고 그 파일이 사용하던 공간을 재사용 가능하게 만드는 것으로 이해했다. 실제 데이터가 원래 저장된 자리에 남아 있을 수 있어서 복구 프로그램이 남은 정보나 내용을 찾아 복구를 시도하는 것이다. 휴지통에서 보관 중인 파일을 골라 복원하는 것과는 방식이 다르다.

과제의 “되돌릴 수 없다”는 설명은 휴지통에서 쉽게 되돌릴 수 없다는 의미로 이해해야 했다. 데이터 복구가 가능할 수도 있지만 반드시 성공하는 것은 아니다. SSD에서는 TRIM과 내부 정리 동작도 영향을 주므로 삭제된 내용이 항상 그대로 남는다고 생각하면 안 된다.

**남은 데이터가 용량을 계속 차지하는지**

그 흔적이 있는 공간은 보통 여유 공간 또는 미할당 공간이라고 부른다는 설명을 들었다. 별도의 숨겨진 휴지통이나 복구용 보관소가 아니었다. 정해진 기간 동안 데이터를 보관하는 것도 아니고, 새 데이터로 덮어써지거나 저장장치가 정리하면 복구하기 어려워진다.

처음에는 따로 지우지 않으면 보이지 않는 곳에서 계속 용량을 차지하는 것인지 걱정했다. 삭제된 파일이 사용하던 공간은 여유 공간으로 계산돼 새 데이터를 저장하는 데 사용할 수 있다. “데이터 흔적이 남을 수 있다”와 “사용 중인 파일로 계속 용량을 차지한다”는 다른 이야기였다.

## 다음에 확인할 것

- 명령어의 뜻은 이해했으니 실제 파일 작업 결과도 과제의 성공 기준과 대조한다. `ls`로 이름과 위치를 확인하고, `cat`으로 파일 내용도 확인한다.
- `cp -i a.log backup/`를 두 번 실행했을 때 왜 두 번째에 질문이 나오는지 직접 확인한다. 첫 번째에는 대상 파일이 없고, 두 번째에는 같은 이름이 있기 때문이다.
- 삭제 전에는 `pwd`로 `mvcp_practice` 안인지, `ls`로 삭제할 대상이 맞는지 확인한다.
- 저장소로 돌아온 뒤에는 `git status`로 올릴 목록을 확인한다. 이 기록 파일과 연습용 폴더를 구분하고, 다른 변경 파일이 함께 있는지도 본다.
- 먼저 이 양식 그대로 기록을 올리고, 다음 단계에서 첫 줄을 `# 2026-10-14 (수) 아침 과제`로 수정한다. `## 막힌 것` 제목 줄 하나를 지우고, 맨 아래에 `## 오늘의 한 줄`과 문장을 추가해 다시 올린다.
- GitHub의 두 번째 커밋에서 삭제된 줄의 빨간 `-`, 추가된 줄의 초록 `+`, 수정된 첫 줄의 빨강·초록 표시를 확인한다. Git은 줄의 수정을 이전 줄 삭제와 새 줄 추가로 보여 준다는 점도 함께 확인한다.
- 필수 과제를 마친 뒤에는 `mv`에도 덮어쓰기 전에 묻는 옵션이 있는지 찾아본다. 추가 실습의 `git diff`에서는 커밋 전에 바뀐 줄을 확인하고, 페이지 보기 화면을 끝낼 때는 터미널에서 `q`를 누른다.
