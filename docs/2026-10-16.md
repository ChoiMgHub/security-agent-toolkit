# 2026-10-16 (금)

## 찾아본 것

서버에서 설정 파일을 고치는 방법:

터미널로만 접속해 작업하는 환경에서는 Vim 같은 터미널 편집기로 설정 파일을 열어 글을 고칠 수 있다. 평소 VS Code에서 하던 파일 내용 작성을 키보드로 진행하는 방법이라고 이해했다. 모든 서버에서 VS Code를 사용할 수 없다는 뜻보다는, 터미널 환경에서도 파일을 편집할 수 있도록 배우는 과제였다.

처음에는 `touch`와 `vim`이 둘 다 새 파일을 만드는 명령이라 같은 것 아닌지 질문했다. 설명을 듣고 역할과 저장 시점의 차이를 정리했다.

- `touch`: 없는 파일이면 내용이 빈 파일을 바로 만든다. 이미 있는 파일의 내용을 지우지는 않고 시간 정보를 갱신한다.
- `vim`: 파일을 열어 내용을 작성하거나 수정하는 편집기다. 없는 파일 이름으로 열었을 때는 저장해야 그 이름의 파일이 만들어진다.
- 새 파일에 바로 글을 쓰려면 먼저 `touch`를 하지 않고 `vim 파일명`으로 열어 작성하고 저장해도 된다.

설명 과정에서 참고한 자료: [Vim 사용자 설명서 — 처음 시작하기](https://vimhelp.org/usr_02.txt.html)

## 오늘 새로 쓴 명령

`vim`

터미널 안에서 파일 내용을 작성하고 수정하는 편집기를 여는 명령이다. 예를 들어 `vim notes.txt`는 `notes.txt`의 편집 화면을 연다.

## vim 으로 한 것

- 입력 모드로 들어가는 키: 소문자 `i`
- 일반 모드로 돌아오는 키: `Esc`
- 저장하고 나가는 명령: `:wq`를 입력하고 Enter
- 저장 없이 나가는 명령: `:q!`를 입력하고 Enter
- 지운 것을 되돌리는 키: 소문자 `u`

`vim notes.txt`를 실행해 편집 화면을 열었다. 처음에는 `Esc`를 누르면 편집기가 종료될 것으로 생각했는데 화면이 그대로 있어 질문했다. Vim에서는 글을 입력하는 상태와 명령으로 조작하는 상태를 구분하며, 일반 모드에서 `:`로 저장·종료 명령을 입력한다는 점을 다시 배웠다.

글을 작성하고 저장할 때의 기본 순서는 `vim notes.txt` → `i` → 내용 입력 → `Esc` → `:wq` → Enter다. `:w`는 저장만 하고, `:q`는 종료를 요청한다. `:q!`는 마지막으로 저장한 뒤의 변경을 버리고 나가는 것이며, 이미 저장한 내용을 이전 상태로 돌리는 명령은 아니다.

과제 설명에서 함께 배운 키도 정리했다.

| 키 | 하는 일 |
|---|---|
| `dd` | 현재 줄 삭제 |
| `yy` | 현재 줄 복사 |
| `p` | 복사한 줄을 현재 줄 아래에 붙여 넣기 |
| `gg` / `G` | 맨 위 줄 / 맨 아래 줄로 이동 |
| `/WARN` 후 Enter | `WARN` 찾기 |
| `n` | 다음 검색 결과로 이동 |
| `:%s/WARN/ERROR/g` 후 Enter | 파일 전체에서 `WARN`을 `ERROR`로 바꾸기 |

학습 기록을 남기기 위해 `touch docs/2026-10-16.md`로 기록 파일을 만드는 단계까지 진행했다.

## 막힌 것

`vim notes.txt`를 실행한 뒤 `Esc`를 눌러도 편집기에서 나오지 않아 종료 방법이 헷갈렸다.

설명을 통해 `Esc`는 종료가 아니라 일반 모드로 돌아가는 키라는 것을 알았다. 저장 없이 나가려면 `Esc`를 누르고 영문 상태에서 `:q!`를 입력한 다음 Enter를 눌러야 한다. 작성한 내용을 저장하며 나가려면 대신 `:wq`를 사용한다.

또 입력 모드에서 `:wq`를 입력하면 명령이 아니라 파일 내용으로 들어가므로, 저장·종료 명령 전에 현재 모드를 확인해야 한다고 정리했다. 이 부분은 안내받은 사용법이며, `E37` 발생 여부나 각 실습의 최종 출력은 아직 이 기록에 따로 남기지 않았다.

## 다음에 확인할 것

- 입력 모드와 일반 모드를 화면에서 구분하고, `Esc`와 종료 명령의 역할을 다시 확인한다.
- `cat notes.txt`로 저장한 내용을 확인하며, 저장하고 종료한 경우와 저장 없이 종료한 경우를 비교한다.
- `dd`로 지운 줄을 `u`로 되돌리고, `yy`와 `p`로 줄을 복사하는 순서를 다시 익힌다.
- 과제의 최종 확인 기준은 로그 네 줄이며, `09:31:10` 줄이 두 번 있고 `WARN` 세 곳이 `ERROR`로 바뀐 상태다. 실제 파일 내용이 이 기준에 맞는지 확인해 결과를 남긴다.
- GitHub에 올리기 전에 `git status`와 선택한 파일 목록을 확인하고, 오늘 기록 파일을 커밋·푸시한 뒤 GitHub에서도 내용을 확인한다. 현재는 기록 파일 생성까지 진행했고 업로드 완료는 아직 확인하지 않았다.
