# day05 경보 판단

- 이름: 최민기
- 날짜: 2026-10-16
- 수업: 오전 3교시 · 문제 3-2

## 이상한 줄

- 줄 번호: **2번, 3번**
- 이유: 인터넷의 외부 PC `192.0.2.7`에서 내부망(INSIDE)의 DB 서버 3306번 포트로 직접 가는 통신이 `permit`으로 허용됐다. 외부 고객은 DMZ의 WEB을 통해 서비스를 이용해야 하므로, 인터넷에서 내부 DB로 직접 접근하는 경로는 차단해야 한다.

1번과 4번은 인터넷에서 공개 WEB의 443번 포트로 가는 경로이고, 5번은 WEB에서 DB의 3306번 포트로 가는 업무용 경로이다. 같은 DB의 3306번 통신이라도 출발지가 외부 PC인지 WEB인지 함께 확인해야 한다고 이해했다.

## 고친 구성도

```text
INTERNET ---- FW ----+---- DMZ    : WEB (443 open)
                    |
                    +---- INSIDE : DB (3306 from WEB only)

FW policy:
  INTERNET -> WEB : TCP/443  permit
  INTERNET -> DB  : TCP/3306 deny
  WEB      -> DB  : TCP/3306 permit
```

## 수정한 접근 조건

| 출발 → 도착 | 포트 | 처리 | 이유 |
|---|---|---|---|
| 인터넷 → DMZ의 WEB | TCP 443 | 허용 | 고객이 웹사이트를 이용하는 데 필요하다. |
| 인터넷 → 내부망의 DB | TCP 3306 | 차단 | 외부에서 내부 DB로 직접 접근하는 것을 막는다. |
| DMZ의 WEB → 내부망의 DB | TCP 3306 | 허용 | WEB이 업무에 필요한 데이터를 이용할 수 있도록 한다. |

`FW policy`는 의도한 접근 조건을 설명하기 위한 표기이다.

## 내가 이해한 것

처음에는 문제를 읽고도 잘 이해되지 않아 손님·접수대·창고 비유로 다시 설명받았다. 인터넷의 외부 PC는 손님, WEB은 접수대, DB는 창고로 생각하면 손님이 접수대를 이용하는 것은 허용하되 창고에 직접 들어가는 것은 막아야 한다는 뜻이다. 접수대가 업무를 위해 창고를 이용하는 것은 필요한 접근이다.

따라서 DB로 가는 연결을 전부 없애는 것이 아니라 **외부의 직접 접근은 막고 WEB의 필요한 접근만 남기는 것**으로 정리했다. DMZ로 구역을 나눴더라도 그 사이의 방화벽 규칙이 잘못 열려 있으면 내부 서버가 노출될 수 있다는 점을 배웠다.

로그에서 확인한 것은 외부에서 DB로 가는 통신이 허용됐다는 사실이다. 이것만으로 DB 로그인 성공이나 자료 유출까지 확인된 것은 아니므로, 실제 피해 여부는 추가 기록으로 확인해야 한다.
