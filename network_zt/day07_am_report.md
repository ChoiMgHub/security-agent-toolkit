- (다) 🔍 경과 12분인 세션이 정산 조회에서는 「유지」인데 권한 변경에서는 「종료」입니다. 왜 자원마다 다르게 판정되나요?
  - 쓸 내용: ① 두 자원의 유지 시간 ② 12분이 각각 어느 조건에 맞는지 ③ 유지 시간이 다른 이유

- (라) 🔍 세션 7 은 경과 30분으로 유지 시간과 같은데 왜 「종료」가 아니라 「재인증」인가요? 코드의 어느 비교 때문인가요?

  - 답: 종료 검사가 `session["age"] > limit`로, ‘크거나 같다’가 아니라 ‘보다 크다’이기 때문이다. 세션 7에서는 `30 > 30`이 거짓이라 종료하지 않는다. 다음 검사인 `30 >= 30 * 0.8`, 즉 `30 >= 24`가 참이므로 재인증이 나온다. 이번 과제에서 정한 경계 조건이며, 모든 시스템의 만료 기준이 반드시 같은 것은 아니다.
### 문제 2-2 · 접속 중에 생긴 변화마다 조치 고르기

- (가) 사례 ① ~ ⑤ 의 조치를 각각 고르고 이유를 적어 주세요.
  - 쓸 내용: 「①: 유지 · 재인증 · 종료 중 하나, 이유 / ②: … / ③: … / ④: … / ⑤: …」 다섯 개
  - 답: 다음과 같이 정리했다.
    - ① 종료: 보안 프로그램이 꺼져 안전한 기기라는 허용 근거가 깨졌다. 본인 확인을 다시 해도 기기 상태가 복구되지 않으므로 이번 과제에서는 세션을 종료한다.
    - ② 종료: 퇴사 처리로 계정을 사용할 자격이 없어졌다. 유지 시간이 남아 있어도 기존 허용을 회수해야 한다.
    - ③ 재인증: 정산 조회 26분은 종료 기준인 30분 초과는 아니지만 재인증 기준 24분 이상이다. 다른 상태가 정상이더라도 정해진 시점에 다시 확인한다.
    - ④ 재인증: 사내 IP에서 해외 IP로 바뀌어 접속 상황이 불확실해졌다. 이번 과제에서는 본인 확인을 다시 요구한다. 주소 변화만으로 공격을 확정하지 않으며, 재인증에 실패하면 종료한다.
    - ⑤ 유지: 권한 변경 2분은 재인증 기준인 5 × 0.8 = 4분보다 짧고, 기기·위치·업무 조건도 그대로다.
- (나) 🔍 ① 과 ④ 는 둘 다 「접속 중에 상황이 바뀐」 경우인데 왜 조치가 다른가요?
  - 쓸 내용: ① ① 에서 바뀐 것과 본인 확인으로 풀리는지 ② ④ 에서 바뀐 것과 본인 확인으로 풀리는지
  - 답: ①은 기기 안전 조건이 나빠진 경우라서 본인임을 확인해도 보안 프로그램이 다시 켜지는 것은 아니다. 따라서 종료한다. ④는 접속 위치 정보가 바뀌어 본인 여부를 다시 확인하는 상황으로 제시되어 있으므로 재인증을 선택한다. 둘 다 변화가 있지만 ‘본인 확인으로 문제를 해결할 수 있는가’가 다르다. 실제 조치는 조직 정책에 따라 달라질 수 있다.
- (다) 🔍 접속 중에는 확인하지 않고 로그인할 때만 확인한다면 ① 과 ② 는 어떻게 되나요?
  - 쓸 내용: ① ① 의 세션이 어떻게 되는지 ② ② 의 세션이 어떻게 되는지
  - 답: 접속 중 상태를 다시 확인하거나 허용을 회수하지 않는다면, ①은 보안 프로그램이 꺼진 기기로도 기존 세션을 계속 사용할 수 있고, ②는 퇴사 처리된 계정도 기존 세션이 만료되거나 별도로 회수될 때까지 접근할 수 있다. 새 로그인을 막는 것과 이미 열려 있는 세션을 회수하는 것은 구분해서 처리해야 한다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 로그인 성공은 영구 허가가 아니며 접속 중에도 허용 조건을 확인해야 한다는 점을 배웠다. 재인증은 본인 확인을 다시 하는 것이므로 기기 안전 문제나 없어진 권한까지 해결해 주지는 않는다. 이번 코드의 `age`는 접속한 뒤 지난 시간이며, 키보드나 마우스를 사용하지 않은 시간과는 다르다. 종료 조건을 먼저 검사하지 않으면 오래된 세션도 재인증으로 잘못 판정할 수 있다는 점도 알았다.

    파일을 만들며 `touch`와 `vim`의 차이도 다시 질문했다. `touch`는 파일이 없으면 빈 파일을 만들고, 기존 파일이 있으면 내용을 지우지 않고 시간 정보를 갱신한다. `vim`은 터미널 편집기로, 없는 파일을 열고 저장하면 새 파일이 만들어진다. Vim을 배운 뒤 파일을 만들 때마다 사용했지만, VS Code에서 만들거나 touch 후 편집해도 결과물에는 차이가 없다는 설명을 들었다. 서버처럼 터미널로 작업하는 환경에 대비해 Vim 기본기를 연습하되, 도구 선택과 전문성 자체를 같게 생각하지 않기로 했다.
## 3교시 · 정책 로그 · 판단과 집행 맞춰 보기

### 문제 3-1 · 정책 로그와 앱 기록을 맞춰 어긋난 요청을 찾아 유형별로 세기

- (가) 내가 채운 코드를 붙여 넣어 주세요.
  - 쓸 내용: `# ←` 일곱 곳에 채운 코드(어긋남 검사 · 유형 정하기 · 개수 세기 · 출력 · 우회 검사 · 우회 개수 · 유형별 개수 출력)
  - 답: 처음에는 `else` 없이 집행 누락만 지정해 112도 집행 누락으로 나왔다. 코드 전체를 보여 주고 설명을 받은 뒤 아래처럼 과집행 분기를 추가했고, 내 PC에서 재실행해 올바른 집계를 확인했다. 다음은 교재의 일곱 빈칸에 해당하는 핵심 처리 부분을 주변 코드와 함께 정리한 것이다.

```python
for p in POLICY_LOG:
    policy_ids.append(p["rid"])
    status = access_status.get(p["rid"])
    expected = EXPECTED[p["decision"]]

    if status != expected:
        if STRENGTH[status] < STRENGTH[expected]:
            kind = "집행 누락"
        else:
            kind = "과집행"

        counts[kind] = counts.get(kind, 0) + 1
        print("[어긋남]", p["rid"], p["user"],
              p["decision"], status, kind)

for a in ACCESS_LOG:
    user = a["user"]
    if a["rid"] not in policy_ids:
        print("[우회]", a["rid"], user, a["status"])
        counts["우회"] = counts.get("우회", 0) + 1

print(counts)
```

- (나) 🔍 출력된 네 건(101 · 108 · 112 · 201)이 각각 무슨 일인지, 「PDP 는 ~했는데 앱은 ~했다」 모양으로 한 문장씩 풀어 적어 주세요.
  - 쓸 내용: 「101: PDP 는 … 했는데 앱은 … / 108: … / 112: … / 201: …」 (201 은 정책 로그에 기록이 없다는 점을 넣어서)
  - 답: 다음과 같이 정리했다.
    - 101: PDP는 거부했는데 앱은 200으로 성공 처리했다. 403으로 막아야 했는데 통과한 집행 누락이다.
    - 108: PDP는 추가확인을 요구했는데 앱은 200으로 성공 처리했다. 필요한 추가확인을 적용하지 않은 집행 누락이다.
    - 112: PDP는 허용했는데 앱은 403으로 차단했다. 정한 것보다 강하게 막은 과집행이다.
    - 201: PDP의 정책 로그에는 대응하는 판단 기록이 없는데 앱에는 성공 응답 200이 남아 있다. 이번 자료에서는 우회로 분류하며, 실제 우회 여부는 로그 누락 가능성 등과 함께 더 확인해야 한다.

- (라) 🔍 PDP 가 「거부」로 정한 요청에 앱이 401 로 답했다면 어떤 유형인가요?
  - 쓸 내용: ① 유형 이름 ② 이유(거부일 때 냈어야 하는 번호와 401 의 세기를 비교해서. 힌트: 200 통과 · 401 추가 확인 · 403 차단)
  - 답: 집행 누락이다. 거부 결정에서 기대하는 응답은 403인데 실제로는 401이므로 필요한 차단보다 약하게 처리했다. 교재의 비교표에서는 401의 강도가 1, 403의 강도가 2라 `1 < 2`에 해당한다. 이 강도 순서는 이번 실습의 분류 기준이고, 실제 HTTP의 401은 유효한 인증 정보가 필요하다는 뜻이지 항상 MFA를 의미하는 것은 아니다.
- (마) 🔍 정상 요청을 막은 과집행은 보안 위험이 낮은데도 왜 조사해야 하나요?

- (바) 🔍 요청 101 이 「거부」인데 앱에서 200 이 된 원인으로 가능한 것을 두 가지 적고, 각각 확인하려면 볼 자료를 적어 주세요.
  - 쓸 내용: 「원인 ①: … / 볼 자료: … / 원인 ②: … / 볼 자료: …」
  - 답: 다음과 같이 정리했다.

if country != "KR":

if count >= threshold:
    total = total + points

# 3. decide 함수 안: 점수에 따른 결정

    return "거부"

    return "추가확인"

if r["kind"] == "정상" and d != "허용":
