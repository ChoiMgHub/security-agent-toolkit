# 정산 포털 로그 점검 결과 (10/21(수))

## 결론
- 연습용 정책 로그에서 seoyeon의 미등록 기기 요청 2건은 모두 거부됐고 02:13 허용은 본인 등록 기기에서 발생했으며, 퇴사 계정 dami의 거부 기록은 4건이다.

## 정정 (3-1에서 읽은 것 중 바뀐 것 · 바뀌지 않은 것)
- 바뀐 것: 3-1에서는 기기가 바뀐 뒤 허용된 흐름을 추가 확인 대상으로 봤다. 새 등록표로 NB-0417이 seoyeon의 등록 기기임을 확인했으므로, 02:13은 ‘본인 등록 기기에서 정책이 허용한 기록’으로 설명을 보완한다. 미등록 기기 NB-7741이 허용되거나 통제를 우회했다는 기록은 아니다.
- 바뀌지 않은 것: NB-7741은 02:10과 15:20에 모두 거부됐다. 실제 요청자와 계정 정보 노출 여부는 미확인이며, 본인의 기기 변경과 제3자의 계정 사용 가능성을 추가 확인해야 한다.

## 근거
- 등록표: NB-0417은 seoyeon, NB-0522는 junho의 기기다. NB-7741은 표에 없고, 퇴사한 dami의 NB-0333 등록은 남아 있다.
- 검색 범위 10분·30분에서는 각각 2건, 60분에서는 jiho 14:40을 포함해 3건이 나온다. 이 수치는 교재의 비교 자료이며, 내가 기준을 바꿔 재실행한 결과로 기록하지 않는다. 검색 후보는 공격 확정 건수가 아니다.
- 내가 직접 실행한 3-1의 거부 이유 집계는 아래와 같고, 전체 20건 중 거부 8건·허용 12건이다. 허용 12건을 모두 정상 요청으로 단정할 수 없으며, 40%라는 거부율만으로 이상 여부를 판단할 수 없다.

```text
미등록 기기 ## 2
퇴사 계정 #### 4
MFA 안 함 # 1
해외 접속 # 1
```

## 권고 (먼저 할 것부터)
1. 조치: 퇴사가 확인된 dami의 계정 비활성화 상태를 확인하고 미처리됐으면 비활성화하며, NB-0333의 기존 사용자 등록을 정리한다. / 막을 수 있는 위험: 퇴사자 계정·등록 정보가 남아 생기는 접근 위험. / 정상 직원에게 생기는 불편: 퇴사자 정보만 정확히 정리하면 정상 직원 영향은 작다. / 순서 이유: 퇴사 사실과 반복 시도가 확인돼 불확실성이 작다.
2. 조치: 정해진 연락 경로로 seoyeon에게 두 시각의 NB-7741 사용 여부를 확인하고, 본인 사용이 아니거나 노출이 의심되면 비밀번호 변경 등 계정 보호를 안내한다. / 막을 수 있는 위험: 계정 도용에 대한 대응 지연. / 정상 직원에게 생기는 불편: 확인 연락과 필요시 인증정보 변경 부담. / 순서 이유: 전체 계정을 막지 않고 해당 사용자의 설명부터 확인한다.
3. 조치: NB-7741의 소유·관리 이력을 자산 대장과 접속 위치·인증 기록으로 대조한다. / 막을 수 있는 위험: 알 수 없는 기기의 반복 시도를 놓치는 것. / 정상 직원에게 생기는 불편: 담당자의 조사 시간이 들고 소유자를 바로 찾지 못할 수 있다. / 순서 이유: 본인의 설명을 독립된 기록으로 확인한다. 2번과 병행할 수 있다.

현재 모든 계정을 막는 조치는 권고하지 않는다. 20건 중 12건은 정책상 허용됐고, 거부 후 허용 2건 중에는 같은 기기의 MFA 재시도로 설명 가능한 건도 있다. 이는 모두 정상이라는 증거는 아니지만 일괄 차단이 정상 업무까지 멈출 수 있음을 보여 준다.
