# 정산 포털 정책 로그 점검 결과

## 결론

- 연습용 정산 포털 기록에서 정책 결정과 실제 응답이 다른 요청 3건, 정책 판단 기록이 없는 성공 요청 1건을 확인했으며, 규칙 조정으로 정상 업무의 불필요한 확인을 줄일 수 있으나 위험 요청을 새로 놓칠 수 있어 통제 경로 조사와 조정안 검증이 필요하다. 계정 도용 여부와 불일치의 정확한 원인은 현재 기록만으로 확인하지 못했다.

## 근거

- **① 3-1 직접 재실행 결과 — 결정과 실제 응답 불일치 3건:** 02:14의 요청 101은 거부했는데 앱이 200으로 성공 처리했고, 13:15의 요청 108은 추가확인을 요구했는데 앱이 200으로 성공 처리했다. 두 건은 정한 조치보다 약하게 처리한 **집행 누락**이다. 17:30의 요청 112는 허용했는데 앱이 403으로 차단한 **과집행**, 즉 정한 것보다 강하게 막은 경우다. 수정 후 집계는 집행 누락 2건·과집행 1건이다.
- **② 3-1 직접 재실행 결과 — 정책 기록이 없는 요청 1건:** 12:34의 요청 201은 앱에 성공 응답 200이 있지만 정책 로그에는 대응하는 요청 번호가 없다. 정책 판단 경로를 거치지 않은 **우회** 가능성을 보여 주지만, 정책 로그 수집 누락 등의 가능성도 있어 우회로 확정하지 않는다.
- **③ 4-1 교재 자료 재계산 — 규칙 조정의 이익과 손실:** 정상 요청을 허용하지 않은 **오탐**과, 위험 요청을 거부하지 못한 **미탐**을 기준으로 11건을 비교하면 현재는 오탐 6건·미탐 0건, A는 0건·1건, B와 C는 각각 0건·2건이다. A에서 요청 11은 해외 49건 조회로, 새 기준 50건에 못 미쳐 해외 점수 30점만 받고 추가확인에 그친다. 이 수치는 교재 자료를 재계산한 비교값이며, 내 PC에서 공유한 기존 출력은 오탐이 모두 9건이어서 수정 후 재실행 확인이 남아 있다.

## 권고

- **통제 경로부터 조사한다.** 우선 거부했는데 통과한 101과 정책 기록이 없는 201을 중심으로, 결정을 실제 접속에 적용하는 **PEP**의 설정·집행 로그와 프록시·라우팅·앱 접근 기록을 요청 번호로 대조한다. 108의 추가확인 누락과 112의 불필요한 차단도 함께 확인하고, 수정 후 결정대로 처리되는지 다시 점검한다.
- **조정안 A를 우선 검증한다.** 대량 조회 기준을 20건에서 50건으로 높이면 이 자료에서 오탐을 6건에서 0건으로 줄이고 B·C보다 미탐이 적다. 다만 해외 49건 조회인 11번을 차단하지 못하므로, 기준 미만의 해외 조회와 반복 조회를 추가로 살피는 보완책을 검토한다. 먼저 오탐 집계 조건을 수정해 내 PC에서 재실행하고, 이후 더 많은 업무 자료로 비교해 적용 여부를 결정한다.
