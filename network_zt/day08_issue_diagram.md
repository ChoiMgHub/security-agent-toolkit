# Day 8 · 정책 로그 이슈 도식
최민기 · 2026-10-21

## 작성 기준
- 교재의 연습용 정책 로그 20줄과 내가 직접 실행한 3-1 결과를 바탕으로 작성했다.
- 코드에서 seoyeon 02:13과 junho 09:44가 ‘거부 후 10분 이내 허용’으로 출력됐다.
- 아래 원인과 조치는 분석 단계의 가설과 제안이다. 사용자 확인이나 추가 기록 조사를 실제로 완료한 것은 아니다.
- 정책 로그의 ‘허용’은 정책 판단 기록이다. 실제 앱 접근 성공이나 기기 소유자까지 이 기록만으로 확정하지 않는다.

## 플로우차트 · seoyeon

```text
[증상] 같은 계정이 02:10에 거부된 뒤 02:13에 허용됐다.
   v
[진단] 같은 계정의 앞뒤 정책 로그를 비교했다. (7일 차 · 정책 로그 분석)
       02:10 NB-7741 거부 / 이유: 미등록 기기
       02:13 NB-0417 허용 / 이유: -
       15:20 NB-7741 거부 / 이유: 미등록 기기
       기기 식별값이 바뀌었고, 오후에도 처음의 기기로 다시 거부됐다.
   v
[원인] 현재 기록만으로 확정할 수 없어 두 가설을 검토한다.
       가설 ① 다른 사람이 seoyeon의 계정 정보를 이용해 시도했을 수 있다.
       지지: 02:10 seoyeon NB-7741 거부 / 미등록 기기
             계정과 기기가 적절히 연결됐는지 확인할 이유가 있다.
             15:20 같은 기기로 재시도한 기록도 있어 경위를 조사할 필요가 있다.
       한계: 미등록 기기라는 사실은 요청자가 다른 사람이라는 증거 자체는 아니다.

       가설 ② 본인이 다른 기기로 시도했다가 기기를 바꿔 다시 요청했을 수 있다.
       지지: 02:13 seoyeon NB-0417 허용 / 이유: -
             기기를 바꾼 뒤 정책이 허용한 흐름은 본인의 정상 재시도라는 설명과도 맞는다.
       한계: 허용 기록만으로 본인 여부나 NB-0417의 실제 등록 상태를 확정할 수 없다.

       (6일 차 · 계정과 등록 기기 검증)
       확인할 기록:
       - 기기 등록표의 소유자, 등록·변경 시점, 당시 유효 상태
       - 정해진 연락 경로로 확인한 본인의 해당 시각·기기 사용 여부
       - 인증·MFA 이력, 접속 출처, 세션 기록
       - 동일 요청의 실제 앱 접근 기록과 집행 기록
   v
[조치] 관련 로그를 먼저 보존하고, 본인 확인과 기기 등록 정보 대조부터 한다.
       MFA 인증 이력도 확인한다. (6일 차 · MFA)
       설명과 기록이 일치하는지 확인한 뒤 조치 범위를 정한다.
       계정 도용 정황이 확인되면 관련 세션 회수·계정 보호 등 대응을 검토한다.
```

## 타임라인 · junho

```text
08:55  junho / NB-0522 / 허용 / 이유: -
09:41  junho / NB-0522 / 거부 / 이유: MFA 안 함
09:44  junho / NB-0522 / 허용 / 이유: -
13:05  junho / NB-0522 / 허용 / 이유: -
```

## 비교 · 로그에서 확인되는 차이
1. 기기 식별값: seoyeon은 02:10의 NB-7741에서 02:13의 NB-0417로 바뀌었다. junho는 09:41과 09:44 모두 NB-0522였다.
2. 거부 이유: seoyeon의 02:10 거부 이유는 ‘미등록 기기’이고, junho의 09:41 거부 이유는 ‘MFA 안 함’이다.

## 도식에 연결한 이전 학습 개념
- [진단]의 같은 계정 앞뒤 기록 비교 → 7일 차 · 정책 로그 분석
- [원인]의 계정과 기기 등록 정보 대조 → 6일 차 · 등록 기기 검증
- [조치]의 추가 인증 이력 확인 → 6일 차 · MFA

## 분석할 때 구분한 것
- 사실: 로그에 적힌 시각·계정·기기 식별값·결정·거부 이유.
- 가설: 제3자 사용 또는 본인의 기기 변경이라는 가능한 설명.
- 미확인: 실제 사용자, 당시 기기 등록 상태, MFA 수행 과정, 앱의 실제 처리 결과.
- ‘지지’는 가설과 기록이 맞아떨어지는 부분을 뜻하며, 그 가설만이 정답이라는 뜻은 아니다.

## 이 교시에 새로 알게 된 것
같은 ‘거부 후 허용’이라도 기기와 거부 이유를 연결해서 봐야 의미를 해석할 수 있다는 것을 배웠다. 타임라인에는 기록에서 확인되는 사실을 적고, 원인 설명에는 가설과 확인할 자료를 나눠 적어야 한다. 정책이 허용했다는 기록만으로 본인 인증이나 실제 앱 접근까지 확인했다고 쓰면 안 된다는 점도 알게 됐다.
