# 2과목 회고 (10/21(수))
최민기 · 네트워크·Zero Trust 학습 기록

## 잘 이해한 것
- 4일 차에 방화벽 규칙을 작성하고 결과를 수정하면서, 필요한 접속만 허용하고 나머지를 제한하는 접근통제의 목적을 배웠다. 6~7일 차에는 정책이 내린 판단과 실제 처리 결과를 따로 확인해야 한다는 점을 배웠다.
- 6~7일 차 오후의 Docker 실습에서 이미지와 컨테이너를 구분하고, 내 PC 포트와 컨테이너 포트를 연결하는 방법을 배웠다. 이미지에 COPY한 파일은 원본을 바꾼 것만으로 실행 화면이 바뀌지 않고, 다시 빌드하고 컨테이너를 교체해야 한다는 점도 확인했다.
- 8일 차에는 내 네트워크 주소 192.168.100.89로 접속했을 때 8081은 000, 8082는 200이 나오는 것을 직접 확인했다. inspect 결과도 8081의 HostIp는 127.0.0.1, 8082는 빈 문자열이었다. 같은 웹 서버라도 포트 공개 주소에 따라 접속 범위가 달라진다는 점을 이해하는 데 도움이 됐다.
- 컨테이너가 Up이어도 nginx가 기다리는 포트와 연결이 다르면 HTTP 응답을 받지 못했다. 8084:8080 서버의 000과 8085:80 서버의 200 및 접속 기록을 비교해, 실행 상태와 실제 서비스 이용 가능 여부를 함께 봐야 함을 배웠다.
- 없는 경로 다섯 개의 404와 index.html의 200을 직접 확인했다. 404 한 건으로 공격이라고 판단하지 않고, 요청 출처·시각·경로·프로그램 정보를 함께 봐야 한다는 점을 배웠다. 이 기록은 내가 만든 실습 요청이다.
- 3-1 코드에서 ‘거부 후 허용’ 두 건과 거부 이유별 2·4·1·1건을 직접 확인했다. 같은 조건에 걸려도 기기와 거부 이유에 따라 해석이 달라질 수 있음을 배웠다. 이슈 도식과 임원 설명 문서는 AI 도움으로 작성했고 cat으로 저장 내용을 직접 확인했다. 문서를 완성한 것과 내용을 충분히 이해한 것은 달라서 쉬운 설명을 반복해서 들으며 정리하고 있다.

## 막힌 것
- 6~7일 차 Docker 학습에서는 이미지가 사진을 뜻하는지부터 헷갈렸고, 컨테이너 삭제 후 파일이 사라지는 경우와 호스트 폴더 연결, 이미지에 COPY하는 방식의 차이를 여러 번 질문했다. 지금도 새 상황에서는 어느 파일을 바꾸고 언제 다시 빌드해야 하는지 확인이 필요하다.
- 7일 차 정책 로그 분석에서는 if의 else 처리가 빠져 직전 유형이 재사용됐고, 국가 코드 KR을 kr로 비교해 집계가 달라지는 문제도 있었다. 주석을 보고 코드를 채우는 것에 비해 변수와 조건문의 실행 흐름을 스스로 설명하는 능력은 아직 부족하다.
- 8일 차 2-1에서 Windows 환경인데 맥북용 명령도 실행했고, 내주소라는 자리 표시를 실제 IP로 바꾸지 않아 접속 시험이 잘못됐다. 이후 ipconfig로 어댑터를 확인하고 실제 주소로 바꿔 000과 200을 확인했다. -p 옵션만 따로 실행해 command not found가 나기도 했다. 앞으로 문제 설명, 운영체제, 현재 위치, 바꿔 넣을 값, 명령어와 옵션을 먼저 구분하겠다.
- 8일 차 3~4교시에서는 사실·가설·미확인 정보를 구분하고, 새 자료로 판단을 정정하며, 조치 순서를 정하는 일이 어려웠다. 작성된 파일을 읽은 뒤에도 설명을 다시 요청했다. 본인 등록 기기의 허용 기록과 실제 사용자가 본인이라는 확인은 다르다는 점을 계속 복습해야 한다.
- 10분·30분·60분 기준별 건수는 교재 비교 자료로 확인했다. 내가 기준을 바꿔 직접 재실행한 것으로 쓰지 않겠다. 사용자 확인, 계정 잠금, 비밀번호 변경 안내, 추가 기록 조사는 실습 문서의 제안이며 실제 수행하지 않았다.
