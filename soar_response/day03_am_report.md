## 3교시 · 허용 목록 IP 와 공유 IP 는 자동 차단에서 제외하고, 차단에 유효 기간(TTL)을 두어 자동 해제하기

### 문제 3-1 · 허용 목록 IP 와 공유 IP 를 판별해 차단하고, 유효 기간이 지나면 자동 해제하기

- (가) 실행한 출력 전체를 붙여 넣어 주세요. 그리고 단계 1 에서 실제로 차단된 IP 와, 차단하지 않은 IP 와 그 이유를 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 실제로 차단된 IP ③ 차단하지 않은 IP 와 각 이유
  - 답: 단계 1에서 `198.51.100.90`이 120분 동안 차단되는 것을 출력으로 확인했다. `192.0.2.10`은 허용 목록의 점검 서버라 차단하지 않았고, `192.0.2.41`은 여러 계정이 함께 쓰는 IP라 담당자 승인이 필요하다고 기록됐다. 단계 3에서 만료된 차단을 해제한 뒤 차단 목록은 `[]`가 됐다. 단계 4에서도 저장된 차단 목록은 `[]`, 조치 기록은 4건이었다. 기록은 차단 요청 처리 3건과 만료 해제 1건이다. `198.51.100.90`은 제공된 파일에서 공유 계정 정보가 조회되지 않는 것이며, 실제 사용자가 없다고 조사한 것은 아니다.

```text
--- 단계 1: 차단 요청 3건
INC-005 198.51.100.90 · 차단되지 않음 → 차단됨 · 경로 스캔 (120분 뒤 자동 해제)
INC-009 192.0.2.10 · 변경 없음 → 변경 없음 · 허용 목록 IP 라서 차단하지 않음
INC-008 192.0.2.41 · 변경 없음 → 변경 없음 · 여러 계정이 함께 쓰는 IP 라서 담당자 승인 필요
--- 단계 2: 차단 뒤 차단한 IP 와 끝나는 시각
차단한 IP: ['198.51.100.90']
차단이 끝나는 시각(분): {'198.51.100.90': 120}
--- 단계 3: 시계를 120분 뒤로 옮기고 시간이 끝난 차단 풀기
INC-005 198.51.100.90 · 차단됨 → 차단되지 않음 · 차단 시간이 끝나 자동 해제
차단한 IP: []
--- 단계 4: 파일에 저장된 값 다시 읽기
차단한 IP: []
조치 기록: 4 건
```

- (나) 🔍 INC-008 의 `192.0.2.41` 은 차단되지 않았습니다. `ip_users.json` 의 값을 근거로 차단하지 않은 이유를 적고, 그대로 차단했다면 영향을 받았을 사용자와 그 영향을 적어 주세요.
  - 쓸 내용: ① `ip_users.json` 의 값 ② 차단하지 않은 이유 ③ 그대로 차단했을 때의 영향

- (다) 🔍 단계 2 의 차단이 만료 시각(120)과 단계 3 의 시계(120)를 근거로 `198.51.100.90` 이 자동 해제된 이유를 적어 주세요. 그리고 유효 기간이 있는 임시 차단이 영구 차단보다 나은 점도 적어 주세요.
  - 쓸 내용: ① 단계 2 의 만료 시각과 단계 3 의 시계 ② 풀린 이유 ③ 자동으로 풀리게 두는 것의 장점
  - 답: 실행 출력의 단계 2에서 차단 만료 시각이 120분임을 확인했다. 현재 시각 0분에 TTL 120분을 더해 계산한 값이다. 단계 3은 모의 시계를 120분으로 옮기고 `expire_blocks()`를 호출한다. 이때 `end_time <= state["clock"]`에서 `120 <= 120`이 참이므로 차단을 해제한다. 임시 차단에 만료 시각을 두면 불필요해진 차단이 계속 남는 일을 줄이고, 사람이 일일이 해제해야 하는 부담을 줄일 수 있다. 이 실습은 실제로 두 시간을 기다리거나 백그라운드 타이머가 동작하는 방식이 아니라, 시각을 바꾼 뒤 만료 확인 함수를 호출하는 방식이다. 단계 3에서 `차단됨 → 차단되지 않음 · 차단 시간이 끝나 자동 해제`가 출력돼 이 해제를 확인했다.

- (나) 🔍 단계 1 에서 `junho` 가 점검에서 발견된 이유를 적어 주세요. 그리고 `dami` 가 단계 2 에서 받은 두 가지 조치와, 잠금만 했다면 유효하게 남았을 접속(세션)을 적어 주세요.
