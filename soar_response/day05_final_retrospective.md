# 5과목 Day 5 최종 회고 (최민기 · 2026-11-16(월))

## 1. 5일 동안 만든 것

11/16 수업에서는 앞선 교재와 실습에서 사용한 모듈을 통합 엔진에 연결했다. 나는 2~4교시 실행 파일을 직접 실행해 알림 처리 결과, 티켓 생성, 정책 점검 출력을 확인했다.

| Day | 날짜 | 엔진과 연결된 파일 | 엔진에서 하는 일 |
|---|---|---|---|
| 1 | 11/9(월) · 11/10(화) | `incident.py` · `config/playbook_registry.json` | 알림의 탐지 이유와 등급을 등록된 규칙·최소 등급에 대조해 실행 후보가 될 조치 절차를 찾는다. |
| 2 | 11/11(수) | `account_actions.py` · `ip_actions.py` | 게이트가 자동으로 판정한 요청의 계정 잠금과 IP 차단을 모의 상태에 적용하고 조치 전후를 남기며, IP 차단 요청에는 해당 IP를 함께 쓰는 계정 수를 제공한다. |
| 3 | 11/12(목) | `ticketing.py` | 알림의 처리 결과와 수행한 조치를 바탕으로 티켓을 만들고 등급별 응답 기한과 다음 할 일을 기록한다. |

## 2. 운영하면 깨질 수 있는 곳 3가지

| 깨질 곳 | 근거(오늘의 파일 · 단계) | 막는 방법 |
|---|---|---|
| 필수 항목이 빠지거나 지원하지 않는 등급이 입력됨 | 2교시 단계 2에서 `INC-402`는 `grade` 누락으로 실패했다. 3교시 단계 2의 시험 기록에서는 `critical`을 알 수 없는 등급으로 표시했다. [오전 보고서](day06_am_report.md) | 엔진에 넘기기 전에 필수 항목과 허용 등급을 검증하고, 거절한 기록과 이유를 보관한다. 처리 중 예외는 알림별로 기록해 나머지 처리를 이어간다. |
| 로그의 결정 값만 믿어 승인 절차 위반을 놓침 | 4교시 단계 2의 교재 비교용 로그에서 게이트 우회 실행 3건이 검출됐다. `INC-405`는 로그에 `자동`으로 적혀 있었으나, 저장된 요청으로 정책을 다시 적용하니 공유 IP 가산점을 포함해 3점으로 `승인 필요`였다. [정책 점검 결과](policy_check.json) | 조치에 사용된 요청과 실행 여부를 기록한다. 점검할 때는 저장된 요청으로 정책 판정을 다시 계산하고, 허용 목록 IP와 VIP 계정의 조치 후 상태도 별도로 확인한다. |
| 조치 후 최종 저장 전에 실행이 중단돼 기록이 남지 않음 | 2교시 실행 코드에서는 알림 처리가 끝난 뒤 로그와 티켓을 파일에 저장한다. 이번 실행에서는 로그 8건과 티켓 7장을 저장했다. 처리 도중 프로그램이 종료되면 앞서 실행한 조치의 기록이 빠질 수 있다. [2교시 실행 코드](day06_2-1_run.py) | 운영에서는 알림별로 조치 시작과 결과를 지속 저장하고, 재시작할 때 완료 기록과 미완료 기록을 대조해 기록 누락이나 조치 중복을 확인한다. |

## 3. 캡스톤 주제와 내 모듈

| 캡스톤 주제 | 쓰는 과목 모듈 |
|---|---|
| SIEM 경보 분류 · 초동대응봇 | `anomaly_detection` + `soar_response` |

- **내가 고르고 싶은 주제** — SIEM에서 내보낸 경보를 초동 대응 티켓으로 연결하는 보안관제 도구를 만들고 싶다. 담당자가 경보의 탐지 근거, 승인 대기 여부, 자동 조치 결과를 티켓에서 확인하고 후속 대응을 판단하는 흐름에 집중한다. 첫 실습에서는 4과목 탐지 결과 파일을 SIEM 경보를 대신하는 입력으로 사용해 이 흐름을 모의로 확인한다.
- **캡스톤 첫날 새 코드 없이 바꿔 볼 설정 파일 2개** — `config/playbook_registry.json`에서는 경로 스캔 플레이북의 최소 등급을 `low`에서 `mid`로 바꿔, 낮은 등급 경보가 차단 후보에서 빠져도 티켓에 남는지 확인한다. `config/approval_policy.json`에서는 별도 모의 실행으로 승인 기준을 3점에서 2점으로 낮춰, 2점 요청이 자동 실행에서 승인 대기로 바뀌는지 확인한다. 같은 입력으로 설정을 하나씩 바꾸고 티켓과 로그를 비교할 계획이다.
- **그대로 가져다 쓸 내 파일 3개** — `engine_input.py`는 탐지 기록의 필수 항목과 등급을 확인하고 알림으로 바꾼다. `soar_engine.py`는 플레이북과 승인 게이트를 거쳐 조치 결과와 티켓을 남긴다. `policy_check.py`는 저장된 요청과 실행 기록을 대조해 승인 절차 위반이나 티켓 누락을 찾는다. 실제 SIEM에서 내보낸 경보를 연결할 때는 먼저 엔진이 받는 입력 형식에 맞춰 필드를 매핑할 계획이다.
